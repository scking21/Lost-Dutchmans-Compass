# Compass walkthrough: draft narration and shot list

Status: updated draft for the personalized discovery-card and readability/layout interface, 2026-10-21. No existing Qloo video artifact was located in this project. This document does not represent an edited, rendered, uploaded or submitted video. Target length: about 90 seconds; an editorial target, not an event requirement.

## Narration

“Lost Dutchman’s Compass starts with a cultural favorite and a public destination. Choose a film, music artist, book or TV show, then let Qloo resolve which one you mean. If a name is ambiguous, you choose the intended match.

“Compass uses the official Qloo harness to request places from that taste signal. The results heading and context show the resolved favorite, category and destination, so you can see what the request actually used.

“These are places returned by Qloo, with its provider order and affinity preserved. Affinity is not a probability about you. The local heritage and outdoor filter checks reviewed catalogue identities; it never fills gaps with invented recommendations.

“Shortlist a place and the next step changes: check the venue’s own opening hours, permission and access requirements. Hide or restore a card without another Qloo call. These local choices don’t change taste scores.

“Open Place evidence to inspect the identity behind a card. Edit your brief to return to your favorite. Changing taste can request a new ranking of retained places, while a new destination needs fresh discovery.

“This is a bounded taste-to-place prototype. Visitor access and safety remain unverified, and a same-model quality comparison has not been completed.”

## Shot list

1. **0–12 seconds: goal and inputs.** Show the compact introduction, public destination and favorite/category fields, visible scope and access notices, and Recommend places action. Show the readiness indicator accurately. Do not imply the default Phoenix/Arrival values have produced results.
2. **12–25 seconds: resolve and confirm.** Show an actual returned match if ambiguity is available in approved footage; otherwise keep this as a narrated capability. Never manufacture a live disambiguation event.
3. **25–42 seconds: query context and place card.** Show the resolved favorite/category/destination, provider position, affinity and unknown-access warning. Keep any local scope exclusions visible enough to understand why fewer than three cards remain.
4. **42–59 seconds: local next step.** Shortlist, hide and restore a returned card. Show the changed next-step text and local count. These controls require no provider call. Do not describe the next-step copy as an AI-generated plan or evidence of the person’s motivation.
5. **59–72 seconds: evidence and navigation.** Expand Place evidence; show the query summary separately from Qloo’s query-level explanation, including its absent state when applicable. Use Edit your brief and show stale results clear after an input change.
6. **72–82 seconds: refinement, only if already captured or separately authorized.** Show the secondary rerank action. A changed favorite/category can enable reranking while capacity remains. Open Scope, test modes and pilot details only when explaining those options. Do not click live discovery/rank for recording under this documentation task. If using earlier ranking footage, label it as the earlier verified build rather than the new card interface.
7. **82–90 seconds: limits.** Finish on the About section or an accurate end card: bounded pilot; access/safety unknown; no completed same-model quality benchmark. No claim that Qloo chose the typography, judged the layout or endorsed this implementation.

## Recording gates

- No provider calls are authorized by this script. Use only already approved footage, or obtain a separate bounded live-recording allowance before a new submission.
- Real-browser rendering of returned cards and mobile layout for the latest readability/layout build have not been verified. Verify those views before representing them as recorded results. Offline DOM tests are not a visual recording.
- If fixture footage is used, label it visibly as synthetic/offline throughout that segment. The preserved fixture lab is a different interface; do not present it as the new live card UI.
- Keep secrets, raw diagnostics and browser/session handles out of footage. Prefer the card’s bounded evidence disclosure to an unredacted full response dump.
- Do not promise a place will appear, an order will change, a venue is open or the experience improves recommendation quality. Live availability and outputs can differ.
- Review the final recording against the exact deployed revision and current event submission instructions before upload. This draft does not authorize upload or submission.
